# BLUE 파란점선 30·2·26 — 오프라인 실측 입력 도구

## 사용 방법

- 파일: [연구 전용 휴대폰 입력 화면](../research/kiwoom_blue_dot_capture_offline.html). GitHub에서 **Raw / Download raw file**로 HTML 파일을 내려받아 모바일 또는 PC 브라우저에서 열어 사용한다. GitHub 코드 미리보기 화면은 HTML을 실행하지 않는다.
- 서버 요청, 키움 로그인, KIS 토큰, API 호출 없이 오프라인으로 작동한다. 기록은 페이지 내 메모리에만 있으며, **JSON 내려받기**로 직접 저장해야 한다.
- 날짜별 **굵은 파란 점선**이 화면에 숫자로 표시되는 경우에만 입력한다. 사용자 원본 수식 설정 30·2·26과 선택된 파란 5pt선이 같은지 수식2/라인설정에서 우선 확인한다.
- 기본 화면에는 앞서 사용자가 올린 스크린샷에서 직접 확인한 **하이브 352820, 2026-11-12, 153,078.28원** 한 건만 채웠다. 해당 실제값의 원본 출처, 세션 미확인 및 수정주가 미확인은 유지한다. 다른 11개 칸은 모두 비어 있다.
- 차트 기준(KRX/NXT)과 수정주가 여부는 확인한 경우에만 상단에서 설정한다. 이 설정은 이후 수동 입력한 숫자에 적용되며 이미 확보된 스크린샷 관측값의 미확인 상태를 임의 변경하지 않는다.
- 날짜/종목별 네 모델 수치는 **고정 공개 MARCAP의 비수정 일봉으로 계산한 연구 가설값**이다. 화면에서 분명히 구분하며 사용자 입력값이나 JSON 관측값으로 자동 대체되지 않는다.
- 저장한 JSON은 `research/kiwoom_blue_dot_30_2_26_observations.json`의 원래 스키마와 호환된다. 저장한 파일을 **JSON 불러오기**로 다시 이어서 입력할 수 있다. GitHub 파일이나 서버 DB를 자동으로 수정하지 않는다.

## 데이터 흐름과 제한

1. 영웅문 MTS/HTS에서 실제 날짜별 점선값과 차트 가격 세션·수정주가 확인
2. 오프라인 HTML에서 실측값만 기록하고 JSON 내려받기
3. 연구용 JSON 입력 파일을 리뷰/검증 후 별도로 GitHub에 반영
4. `blue_dot_direction_risk_study.yml`의 `main` 수동 `mode=study` 실행으로 4개 계산 가설 대조, 증거 부족 게이트 확인
5. **6개 값이 모두 모여도 공식 함수/선 대응, 가격 정합성, 실체결·독립 성과 검증까지 완료됐다는 뜻이 아니다.**

## 검증·안전

- 정적 도구 단독으로는 계좌·세션 정보·체결 이력을 수집할 수 없다. 차트 숫자는 사람이 직접 입력한 출처가 있는 관측치일 뿐 공인 증권사 데이터 익스포트가 아니다.
- 숫자·날짜·종목이 유효하지 않은 JSON이나 중복 날짜는 불러오지 않는다. 누락일 0원/모델값 자동 대체 금지.
- 이 PR은 HTML 및 오프라인 정적 검사에만 해당하며 운영 Worker, UI, D1/Turso, KIS, 종목검색, AI 추천, 손절/익절 로직, 주문 기능에 영향 없음.
