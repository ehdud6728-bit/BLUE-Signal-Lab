## A. 과거 일봉 + R1.1 패턴 + 선택적 전체 기술지표 수동 묶음

워크플로: [BLUE Turso Bounded History + Pattern Replay](../.github/workflows/blue_turso_history_research_batch.yml)

1. **`main`에서 `plan`:** 지정 시작·끝 날짜를 검사합니다. DB/KRX/KIS/Gemini 접근 **0회**. 현재로부터 760일 이내, 마지막 날짜는 한국 시간 어제 이전, 최대 **7달력일/5평일**. 자동 예약 없음.
2. **`dry_run`:** 정확한 날짜별 KRX KOSPI·KOSDAQ EOD 원천을 요청하고 모든 범위의 EOD·과거 R1.1 연구 출처/일자/원장·해시를 검증합니다. 이때 **동일한 해시 검증 EOD 파일을 R1.1 스캐너의 목표일에 재사용**하고 marcap 과거 봉은 지표에 필요한 이전 이력에만 사용합니다. `observed_stocks`가 해당 KRX 목표일 건수와 다르면 거부하며, 공급자를 다시 호출하지 않습니다. **Turso 연결/쓰기 없음**. `include_indicators=true`일 경우 2,600여 종목 전부의 지표도 미리 검증하되 저장하지 않습니다.
3. **`apply`:** 각 날짜의 자료 **전부** 사전 검증에 성공한 뒤에만 기존 엄격·멱등 Turso EOD writer→패턴 스냅샷 writer를 순차 사용합니다. 승인 문자열은 `blue-turso-history-시작일-끝일` (예 `blue-turso-history-2026-11-09-2026-11-12`)과 정확히 일치해야 합니다. `include_indicators` 저장은 별도 `confirm_indicators=blue-turso-all-indicators` 승인까지 필요합니다. D1 SQL 0회, KIS tokenP 0회.

**중요:** 휴장일이 범위에 포함되면 거래소 공식 캘린더를 추정해 자동 건너뛰지 않습니다. 소스 검증이 실패하면 그 범위를 중단하고 휴장 여부를 확인한 뒤 범위를 다시 선택합니다. 기존 날짜의 원천·가격·감사 해시가 달라졌을 경우 기존 자료를 변경하거나 삭제하지 않고 실패시킵니다. 일부 날짜만 성공한 후 네트워크 오류가 발생하면 기존 멱등 writer로 원장을 확인하고 재실행해야 합니다. **1~2년 전체 저장은 복수의 제한된 날짜 범위 작업**이 필요하고, KRX 공급자 보유 기간·호출량/용량·GitHub Actions 시간을 별도 검증해야 합니다. 현재 코드가 한 번의 실행으로 2년을 끝낸다는 뜻은 아닙니다.

**2026-11-20 실행 주의:** [과거 4일 `dry_run` #44667107812](https://github.com/ehdud6728-bit/BLUE-Signal-Lab/actions/runs/44667107812)는 이전 버전에서 성공했으나, EOD 10,651건과 과거 marcap 기반 패턴 분석 관측 10,451건이 달랐습니다. 그때의 패턴 798건은 정합성 확인 전 수치입니다. 같은 KRX 데이터에 정렬되도록 개선한 버전을 병합한 후 **먼저 해당 4일 `dry_run`을 다시 실행**하고, 이후 `apply` 여부를 별도로 결정해야 합니다. 기존 D1 및 Turso 값은 덮어쓰지 않습니다.

## B. 단기·장기 패턴 첫 익절/손절 연구 및 선택적 게시

워크플로: [BLUE Turso Short+Long Pattern Exit Study](../.github/workflows/blue_turso_pattern_exit_study.yml)

1. **`plan`:** 가격/DB/시크릿 0회. 대상은 최근 감사 EOD 5·10·20·60·120·250·500일 중 하나.
2. **`study`:** Turso **SELECT 전용**. EOD 원장 vs 실제 모든 해당 날짜의 행 수, 연구 원장 vs 신호 건수·원천 해시 확인 후, 검증된 저장 가격만 JSON으로 내보냅니다. 100,000 매칭 행·350,000 가격 행 안전 상한을 넘으면 자동 중단합니다. GitHub 아티팩트에는 연구 **요약 보고서만** 보존합니다.
3. 순수 오프라인 `pattern_exit_study.py`: 신호 **다음 거래일 시가**부터 진입, 사전 고정 익절/손절/최대 보유기간 6개 정책의 **첫 도달**을 계산합니다. 종가 오염·앞날 참조 금지, 손절 갭은 불리한 시가, 하루 고저가 양쪽 도달은 손절 우선, 미완성은 `PENDING`, 종목/거래일 경로 누락은 제외. 5·10일 신호 발생 변화와 실제 후속 5·10일 **성숙 성과**를 분리합니다. 최근 25%는 파라미터 선택에 사용하지 않는 홀드아웃이며, 훈련/검증 기간 중첩은 제외합니다. 소표본은 탐색 사례로만 표시합니다.
   - **추가 고저가 관측:** 신호 발생 최근 5·10·20·60일 창과 별도로, 다음 거래일 시가 기준 **보유 D+5/10/20/60거래일** 고가 최고·저가 최저의 중앙 변동률을 계산합니다. 정확히 필요한 전 거래일 가격 경로와 감사가 없으면 미성숙/누락으로 제외합니다. 패턴별 성숙 표본이 3건 미만이면 성과로 나열하지 않습니다. 날짜가 다른 극값만 `고가 먼저/저가 먼저`를 구분하고 **같은 날 고가·저가의 선후는 알 수 없다**고 기록합니다. 이는 실제 체결·가격 도달 가능성 검증을 대신하지 않습니다.
4. **`publish`:** 별도 승인 문자열 `blue-turso-exit-research-only`가 정확할 때에만 **요약 보고서**를 `blue_pattern_exit_reports_v1`에 추가하고 동일 날짜의 다른 결과 덮어쓰기 거부. 원본 EOD/신호·D1 수정 없음. 새 API `/api/research/exit-study`와 Turso `AI 패턴` 탭에서 조회할 수 있습니다. 미게시라면 화면에 `연구 결과가 아직 게시되지 않았습니다` 표시.
   - 기존 게시된 불변 보고서(V1)가 신규 고저가 필드 없이도 정상 표시되도록 유지합니다. 새 필드는 새로운 날짜 범위에서 별도 `study` 후 **사용자 승인한 게시 건**에만 표시됩니다. 코드 병합/배포만으로 새로운 연구 통계가 생기지 않습니다.

### 추천 보류 게이트

- KRX 공식 거래일 연속성/휴장일 보완, 기업행동·수정주가, 유동성/비용, 지수/업종 시장 기준선, 발생일 당시 알 수 있던 특징, 독립 시점 분리·종목 중복/선택 편향이 **아직 검증되지 않았습니다.** 보고서에는 이들을 임의로 `true`로 만들지 않습니다.
- 과거 연구가 데이터만큼 쌓여도 **AI 추천·확정 목표가·예상 수익률은 생성하지 않습니다.** 5/10/20/60 vs 120/250/500의 표본/익절·손절 탐색을 앱에서 보며 다음 독립 검증을 추진할 준비 단계입니다. 실제 AI 관찰 후보와 시장/업종 맥락은 검증된 소스와 별도 승인이 확보된 뒤 추가합니다.

## 배포와 순서

1. 이번 PR CI 성공 → 사용자 병합 → 기존 API 수동 배포 → 기존 웹 정적 배포. 자동 DB 쓰기 없음.
2. 소규모 결측일 하나로 `plan` → `dry_run` 결과 확인. 비용/원천·중복 저장 확인과 **운영자 별도 승인** 전에는 `apply` 금지.
3. 역사 자료가 확보되면 `study`를 읽기 전용 실행하고 결과/부족 구간 확인 → 독립 데이터 검증. 사용자가 명시적으로 승인한 경우에만 `publish`로 연구 요약을 앱에 노출.
4. 충분한 성숙·독립 검증 전까지 **AI 패턴 출현 빈도 ≠ 성과/추천**, 시장/업종 상태 `미검증` 원칙을 유지합니다.
