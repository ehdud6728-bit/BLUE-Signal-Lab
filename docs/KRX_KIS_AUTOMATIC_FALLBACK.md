# KRX 실패 시 KIS 2차 수집 / 검색 시 누락 최신가 보완

> 2026-11-20 KST. 코드·무비밀 테스트 기준 안내. 실제 Worker 배포 및 KIS 운영 호출은 별도 확인한다.

## 1. 일일 확정 KRX → KIS 2차 경로

- GitHub `blue_turso_daily_verified_eod_auto.yml`은 기존과 같이 **KRX pykrx → 독립 KRX Open API** 정확일·전체시장 검증을 먼저 수행한다.
- 둘 다 실패하면 `apply`(예약 실행 또는 승인된 수동 실행)에서 **추가 파일럿/FULL 플래그 없이** `krx-kis-fallback-collect.mjs`가 기존 암호화 Turso 금고의 **유효한 KIS 토큰을 재사용**하여 공식 `inquire-daily-price`를 정확 거래일 기준으로 조회한다. 기존 비밀번호/토큰을 로그에 출력하거나 `tokenP`를 호출하지 않는다.
- 기준 종목은 직전 **실제 행 수까지 감사 완료한 KRX 전체시장 일봉**에서 가져온다. KIS는 종목별 API이므로 1,750ms 이상 간격(분당 약 34개 이하), 20개 유효 건당 체크포인트를 쓰고, 재실행에서는 이미 유효하게 저장된 종목을 건너뛴다. 2,600~2,700종목을 모두 조회하면 최소 약 76~79분이며 API 응답·DB 지연이 추가된다.
- 날짜가 7일을 초과해 오래됐거나 기준 KRX EOD가 불완전하면 중단한다. KIS가 거래일을 정확하게 응답하지 않거나 HTTP 429/`EGW00201`이면 종료/감속하지 않고 **다음 재실행까지 중단**한다. 같은 날의 완성된 KRX 감사가 있으면 KIS를 호출하지 않는다.
- 수집물은 **Turso KIS 최신/이력 및 `blue_kis_provisional_daily_v1`**에만 기록한다. 저장했더라도 `KIS_PARTIAL_PROVISIONAL`이며 `blue_eod_daily_v1`, 확정 원장, BLUE 패턴·전체 지표에 기록하지 않는다. KRX와 KIS는 무조건 같은 표본을 공급한다는 보장이 없으므로 미조회 종목을 완료라고 하지 않는다.
- `dry_run`은 KIS API 호출/신규 저장을 하지 않고 **기존 저장분만 감사**한다. KRX 실패시 KIS 수집이 실패해도 읽기 전용 게이트는 수행되어 남은 부분 자료를 확인할 수 있다.

## 2. 검색 누락 최신가 → KIS 자동 조회

- 앱 `종목 검색`에서 Turso 연구 종목 및 저장 KRX/KIS 가격을 먼저 읽는다. 조회 결과 **오늘 기준의 확인가가 없는 종목**은 검색과 동시에 Access/Origin 보호 `POST /api/eod/quotes/refresh`로 자동 조회한다. 사용자는 검색 결과를 기다리지 않고 바로 볼 수 있다.
- 해당 페이지 중 최대 100개 **고유 종목을 순차 처리**하며 브라우저에서 약 5.1초 간격을 두고 진행률을 표시한다. 서버의 종목별 20초·전체 12회/분 한도, 기존 유효 토큰 재사용, 신규 `tokenP` 금지, 장중/당일 KIS 일봉 출처 검증이 적용된다. 다른 탭/사용자와 한도를 공유하므로 다수 종목의 새 시세가 즉시 모두 확보되지는 않는다.
- 오후 15:20~22:00 KST에는 종목별 KIS **날짜 일치 일봉**으로만 보완하고 `잠정`으로 저장한다. 이 외 장외/휴장 시에는 기존 저장 시세와 기준일을 그대로 표시한다. 종목별 수동 조회 버튼은 계속 사용 가능하다.
- **검색일 종가·과거 거래대금 필터·패턴 신호는 변경하지 않는다.** `최근 확인가`만 새로운 KIS 검증 관측으로 갱신한다. 검색일이 오늘이면 당일 KIS 관측도 표시할 수 있지만, 미래 수익률/검색 이후 기간 최고가로 계산하지 않는다. 동일 날짜의 감사 완료 KRX 종가가 우선한다.
- 자동 호출에는 **Collector/API/웹의 해당 PR 버전 배포** 및 `TURSO_INSTANT_QUOTES_ENABLED=true` Worker 운영 승인 플래그, 기존 KIS 암호화 토큰이 필요하다. 플래그가 OFF이거나 토큰/원천이 없으면 새 시세를 만들어 내지 않는다. 전체시장 KIS 백그라운드 FULL 모드는 별개이며 이 기능이 켜지지 않는다.

## 3. 수동 검증 순서

1. PR CI 통과·사용자 병합 후 Collector → API → 웹을 순차 배포한다. 기존 `TURSO_MIRROR_ENABLED=false`를 보존한다.
2. [Turso KIS Instant Quote Control](https://github.com/ehdud6728-bit/BLUE-Signal-Lab/actions/workflows/blue_turso_instant_quotes_control.yml)에서 `mode=enable`, `confirm_worker=blue-market-collector`를 **사용자 승인하에** 설정해야 자동 검색 갱신이 동작한다.
3. 정상 거래일 검색에서 기존에 최근가가 없던 1~2개 종목만 먼저 살펴 `최신 확인가` 출처/시각/가격과 KIS 사용량을 확인한다. D1에 자동 신규 조회를 요청하지 않는다.
4. 예약된 일일 `apply`에서 KRX 양쪽 실패시 KIS 단계가 실제로 호출되고, 일부라도 KIS 최신·잠정 자료만 저장되었는지 Actions·Turso 읽기 전용 게이트로 확인한다. 실제 KIS 2,600개 호출/속도/비용은 실행 전 예측이며 실측 완료가 아니다.

비밀키·원본 공급자 응답을 기록하지 않으며, KIS가 최신 일봉을 제공하지 못한 종목은 끝까지 미수집으로 남겨야 한다.
