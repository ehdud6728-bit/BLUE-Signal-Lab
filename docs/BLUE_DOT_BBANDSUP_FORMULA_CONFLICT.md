# 키움 파란점선 원본 함수명과 실제 지표값의 충돌 감사

## 확인된 자료와 불확실성
- 사용자 원본 파란 점선 수식: `SHIFT(BBandsUp(설정값,설정값2),설정값3)`, 주 설정 **30/2/26**. 붉은 실선이 같은 위치에 겹쳐 표시되었던 것으로 사용자 설명.
- 외부 키움 수식 설명 글에서 `BBandsUp(Period,D1)`은 보통 **상단**, `BBandsDown`은 하단, 기준은 통상 HLC3라고 설명한다. 다만 이 설명은 **제3자 게시물**이며, 키움 HTS 버전·적용 가격 소스·수식2와 화면선 매핑까지 공식 확인한 문서가 아니다.
- 이미 사용자 제공한 스페코 2026-10-21/22/23의 30·2·26 숫자 1,529.14/1,531.15/1,533.75원은 고정 MARCAP **HLC3 하단** 3/3 표시 일치, HLC3 상단 0/3이며 평균 절대 오차 약 118.97원. 이것을 근거로 `BBandsUp`이라는 **상단 함수명**이 하단값을 뜻한다고 결론 내리는 것은 오류이다.
- 롯데칠성 35·2·26 2일 사용자 제공 숫자는 HLC3 상단이 네 모델 중 가장 가까우나 정수 표시 기준 0/2 불일치. 35주기 사례를 메인 30주기 연구 표본에 섞지 않는다.
- 하이브, 캐스텍코리아, 아진산업, 에스엘의 실제 굵은 파란색 점선 '선값'은 숫자로 확인되지 않았다. 그림에서 상단 실선과 하단 점선을 혼동한 적 있으므로 육안으로 임의 숫자 채택하지 않는다.

## 공개 자료 (권위와 제약 구분)
- [키움 공식 수식관리자 안내](https://download.kiwoom.com/hero4_help_new/012.htm): 수식관리자에서 기본함수의 함수설명 확인 가능. 공개 HTML에서 `BBandsUp`의 특정 입력가격/파라미터 계산을 직접 확인하지 못함.
- [영웅문 HTS 함수 제3자 정리](https://sjsks3.tistory.com/entry/키움증권-영웅문-HTS-수식-및-함수-정리): BBandsUp=상단/BBandsDown=하단, TypicalPrice=(H+L+C)/3 산식 설명.
- [영웅문 볼린저밴드 계산 제3자 설명](https://wikidocs.net/89275): TypicalPrice를 이용해 중심선·상/하단을 구성하는 식 설명.
- [수식관리자 BBandsUp 제3자 안내](https://thinkjb.tistory.com/entry/키움증권-영웅문-수식관리자-Valuewhen-함수에-대해서-알아보자): 상한선이라는 관례. 출처가 실제 함수 내부 소스코드/인증자료는 아님.

## 변경
- `scripts/blue_dot_formula_conflict_review.py`는 기존 고정 SHA 두 보고서 `original_formula_comparison.json`과 `kiwoom_30_2_26_audit.json`, 관측 대기 `kiwoom_30_2_26_observed_match.json`을 **다시 내려받지 않고** 읽음.
- 함수명 'Up'과 스페코 하단 일치 간 충돌을 명시적으로 검출. 롯데칠성 비교는 별도 표시. 네 화면 사례의 종가·당일 고저 범위 안에 가상의 HLC3 상/하단값이 드는지 단순 비교하되 **시각적 일치 및 실제 돌파 인증은 하지 않음**.
- `formula_conflict_report.json`: 수식 미확정 상태·불일치 계량·검증 선행조건·실제 점선 수치 0건 보존. 임의로 사용자의 BBandsUp을 BBandsDown으로 바꾸지 않음.

## 다음 실증 절차
키움의 **해당 파란점선 수식2 선택 상태 + 함수설명/설정 + 일봉 한 날짜의 선값**이 같은 화면에서 연결되는지 확인. 정규장/통합장, 수정주가 사용 여부 기록. 그다음 **서로 다른 30·2·26 종목 최소 2개**에서 동일 날짜별 점선값을 확보해 원수식 후보와 대조. 완료 전 신호 추천·마감베팅 규칙·골드테두리 적용 금지.
