# 키움 파란점선 원본 함수명과 실제 지표값의 충돌 감사

## 확인된 자료와 불확실성
- 사용자 원본 파란 점선 수식: `SHIFT(BBandsUp(설정값,설정값2),설정값3)`, 주 설정 **30/2/26**. 붉은 실선이 같은 위치에 겹쳐 표시되었던 것으로 사용자 설명.
- 외부 키움 수식 설명 글에서 `BBandsUp(Period,D1)`은 보통 **상단**, `BBandsDown`은 하단, 기준은 통상 HLC3라고 설명한다. 다만 이 설명은 **제3자 게시물**이며, 키움 HTS 버전·적용 가격 소스·수식2와 화면선 매핑까지 공식 확인한 문서가 아니다.
- 이미 사용자 제공한 스페코 2026-10-21/22/23의 30·2·26 숫자 1,529.14/1,531.15/1,533.75원은 고정 MARCAP **HLC3 하단** 3/3 표시 일치, HLC3 상단 0/3이며 평균 절대 오차 약 118.97원. 이것을 근거로 `BBandsUp`이라는 **상단 함수명**이 하단값을 뜻한다고 결론 내리는 것은 오류이다.
- 롯데칠성 35·2·26 2일 사용자 제공 숫자는 HLC3 상단이 네 모델 중 가장 가까우나 정수 표시 기준 0/2 불일치. 35주기 사례를 메인 30주기 연구 표본에 섞지 않는다.
- 하이브, 캐스텍코리아, 아진산업, 에스엘의 실제 굵은 파란색 점선 '선값'은 숫자로 확인되지 않았다. 그림에서 상단 실선과 하단 점선을 혼동한 적 있으므로 육안으로 임의 숫자 채택하지 않는다.

## 다음 실증 절차
키움의 **해당 파란점선 수식2 선택 상태 + 함수설명/설정 + 일봉 한 날짜의 선값**이 같은 화면에서 연결되는지 확인. 정규장/통합장, 수정주가 사용 여부 기록. 그다음 **서로 다른 30·2·26 종목 최소 2개**에서 동일 날짜별 점선값을 확보해 원수식 후보와 대조. 완료 전 신호 추천·마감베팅 규칙·골드테두리 적용 금지.

## SHIFT(+26)의 방향과 후속 증거 확보 (2026-11-23)
- 키움 `Shift(A,N)`은 N이 양수이면 **차트 오른쪽으로 이동**, 음수이면 왼쪽으로 이동한다고 공개 함수 자료에 설명되어 있다. 따라서 26봉 **우측** 이동의 시점 t 표시값은 t-26봉의 계산값이며 pandas `.shift(+26)`와 방향이 같다.
- 참고: [키움 내장함수 Shift 표](https://hot-t.tistory.com/36), [함수 원문을 인용한 Q&A](https://www.yesstock.com/community/qna-type1-dtl?postCategory=&postNo=89006&searchType=&searchValue=). 해당 설명은 2차 자료/전사로, 사용자 화면의 파란점선 연결을 직접 인증하지 않는다.
- 별도 단위 테스트에서 **HLC3 상·하단을 30봉으로 계산한 뒤 26봉 전 값이 t에 표시되는지** 확인하며 잘못된 `.shift(-26)` 방향 반전 및 미이동을 차단한다. `BBandsUp` 함수 자체가 하단이라는 의미로 바꾸지는 않는다.

### PC 영웅문4 화면에서 선-수식 연결 증거 확인
1. 차트의 파란점선 **해당 사용자지표**를 확인하고 `수식관리`에서 **수식2** 내용 및 **지표조건설정**의 세 변수 30·2·26을 기록한다.
2. 같은 지표의 **라인설정** 탭에서 **수식2 행의 표시 여부·파란색·원형 점선·굵기**를 확인한다. 붉은색 실선이 동일 가격에 겹치면 해당 선은 잠시 숨겨 단독 확인한다.
3. 같은 날짜의 **지표값**(차트 지표값 표시/데이터윈도우에서 조회 가능한 경우)을 저장하고, KRX/NXT·수정주가 상태를 함께 기록한다. HTS 메뉴 명칭은 버전에 따라 다를 수 있으며 모바일 앱에서는 PC와 동일 UI를 가정하지 않는다.
- 키움 공식 도움말: [수식관리자 수식/라인설정](https://download.kiwoom.com/hero4_help_new/012.htm), [종합차트에서 지표값 표시](https://download.kiwoom.com/hero4_help_new/010.htm), [HTS 사용자지표를 MTS로 내보내기](https://download.kiwoom.com/hero4_help_new/0600.htm).
- 아직 확인 안 된 핵심: **이미 기록한 스페코 점선값이 같은 수식2/같은 차트에서 추출됐는지**. 추가 HTS 증거 없이는 브로커 매수신호 0건, 추천/운영 적용 보류.

## 실제 MTS '라인설정' 사용자 스크린샷 검증 (2026-11-23)

- 사용자 제공 이미지의 지표 제목은 **'파란점선'**, 상단은 **라인설정** 탭. 미리보기에는 파란 원형 점선이 굵게 표시됨.
- **첫 행** '중심 %Period%, %D 1%'는 파랑/1pt이며 현재 표시 **해제**.
- **둘째 행** '파란점선'은 파랑/5pt이며 표시 **선택**.
- **셋째 행** '파란점선'은 빨강/5pt이며 표시 **해제**. 과거 붉은 실선이 겹쳤다는 관측과 별개로, **이번 화면에서는 빨간 행이 켜져 있지 않음**.
- 기존 사용자 제시 수식 순서가 수식1 BBandsC, 수식2 SHIFT(BBandsUp(...),26), 수식3 SHIFT(BBandsDown(...),26)이므로 **둘째 행 파란 5pt → 수식2** 대응이 *강하게 시사됨*. 그러나 이 스크린샷 자체에 각 행의 **수식 문자열은 표시되지 않기 때문에** 원본-라인 연결은 '순서 일치 추정'으로 구분.
- 화면은 **지표 선값 숫자를 표시하지 않으므로** 이미 기록한 스페코 하단선 3/3 수치 일치가 실제 BBandsUp 라인일치임을 증명하지 않는다. 원본 수식과 가격 기준을 검증하기 전 기존 HLC3 하단 연구를 실전 매매 신호로 승격하지 않는다.
- 본 이미지는 사용자 채팅에서만 확인했으며, 원본 사진 파일은 GitHub에 업로드하지 않고 확인한 기술적 사실만 문서화했다.
